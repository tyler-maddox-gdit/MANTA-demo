QA and release: the Workbench

Test and Release. The scan is evidence; the tester is the judgment.

  • Launch a scan from the browser, watch it run, read the report. No command line.
  • Add what no rule can see, give a verdict on what a rule could only flag, re-measure a fix on the spot. Everything is recorded on the run itself.
  • Focus order and the keyboard rules give the tester evidence for the judgment calls, such as a dialog that lets focus walk out of it (WCAG 2.4.3).
  • The conformance report (the ACR) and the defects export come from the same run. Nothing is retyped.

DevOps: the pull request gate

Integrate. Legacy debt tolerated, new debt blocked, and this time fixed before it lands.

  • The same gate the developer ran, now on every pull request as a required check: while it is red, the change cannot merge.
  • MANTA posts what it found and the fixes as review suggestions. One click applies them in one commit, and the gate goes green.
  • The findings also go to GitHub code scanning (as SARIF), so accessibility sits beside every other scanner, tracked the same way.
  • Every night, a scan signs in and reaches the pages no pull request touches.

Development: the developer's gate

Plan and Develop. Accessibility is part of the definition of done, and the developer learns first.

  • Before any code, the WCAG checklist is the acceptance criteria for the feature.
  • The developer scans the site on their own laptop. Known debt is tolerated; new debt fails the change, the way a failing unit test does. The count only goes down.
  • Every finding names the source file and line that wrote it.
  • A developer who does not know what button-name means asks MANTA's AI skills: they group the findings by cause and write the fix, and one command applies it.
